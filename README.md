# Uptime Kuma — сборка Asvad Logistic

Готовый набор, чтобы [Uptime Kuma](https://github.com/louislam/uptime-kuma) показывал логотип и название
**Asvad Logistic** и обновлялся до последней версии без ручных правок.

GitHub Actions каждый день проверяет новую версию Uptime Kuma 2.x, подставляет логотип,
собирает Docker-образ и публикует его как `ghcr.io/sa1d77/uptime-kuma-asvad`.

## Что внутри

| Файл | Назначение |
|---|---|
| `branding/` | Логотип и иконки. Копируются в `public/` поверх оригинальных (`logo.png`, `favicon.ico`, `icon.svg` …) |
| `patch.py` | Меняет логотип и надписи: шапка, мобильное меню, 404, первичная настройка, «Настройки → О программе», вкладка браузера |
| `.github/workflows/build.yml` | Автосборка образа |
| `update-kuma.sh` | Обновление на сервере одной командой, с бэкапом |

## Обновление

На сервере (Ubuntu):

```bash
./update-kuma.sh
```

Скрипт скачает свежий образ, покажет текущую и новую версию, сделает бэкап базы в `~/kuma-backup-<дата>`
и перезапустит контейнер. Конкретная версия или откат: `./update-kuma.sh 2.5.6`.

Скачать скрипт на новый сервер:

```bash
curl -fsSLO https://raw.githubusercontent.com/SA1D77/uptime-logo/master/update-kuma.sh && chmod +x update-kuma.sh
```

## Смена логотипа

1. Замените файлы в `branding/` и сделайте commit.
2. Сборка запустится сама (вкладка **Actions**).
3. На сервере: `./update-kuma.sh`.

## Ручная сборка

**Actions → Build Asvad Uptime Kuma → Run workflow**. Поле «Версия» можно оставить пустым.

## Если сборка упала

Обычно это значит, что в новой версии Uptime Kuma изменилась разметка и `patch.py`
не нашёл нужный блок: в логе будет `ОШИБКА: не найдены блоки`. Сервер при этом продолжает работать
на прошлой версии. Нужно поправить шаблон в `patch.py`.
